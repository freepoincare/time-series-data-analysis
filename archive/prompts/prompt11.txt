[Answer]

  The errors all share the same root cause: summer_like_percent and winter_like_percent columns don't exist in monthly_temperature_characteristics.csv on Streamlit Cloud
  — because the cloud deployment doesn't run analysis.py to regenerate the CSV; it reads whatever CSV is committed to the repo.

  The cloud CSV was saved before those columns were added. The fix is to compute the columns on-the-fly in app.py's load_all_data() as a fallback, so the app works
  regardless of which version of the CSV is present.

배포 환경(Streamlit Cloud)에서 발생하던 KeyError 원인을 찾아 해결하였습니다.
  ──────
  ### 1. 원인 분석

  배포 환경(Streamlit Cloud)에서는 analysis.py 파이프라인을 직접 재실행하지 않고 레포지토리에 커밋된 CSV 파일을 바로 읽습니다.

  • 기존 app.py는 monthly_temperature_characteristics.csv를 고정적으로 참조하고 있었으나, 최근 파이프라인 개편으로 해당 파일명이 monthly_ratio.csv로 변경되었거나 배포
  환경의 구버전 CSV에는 summer_like_percent / winter_like_percent 컬럼이 없어 웹에서 KeyError가 발생했습니다.
  ──────
  ### 2. 수정 사항 (app.py:36-58)

  app.py:29-70 함수에 Fallback 및 컬럼 자동 생성 로직을 추가하여 배포 환경의 어떤 CSV 상태에서도 오류 없이 실행되도록 개선했습니다:

  1. 파일 호환성 지원: monthly_ratio.csv와 기존 monthly_temperature_characteristics.csv를 순차적으로 감지하여 로드하며, 파일이 없더라도 dataset_processed.csv에서 즉시
  집계하여 복구합니다.
  2. 컬럼 보장: 로드된 데이터프레임에 summer_like_percent / winter_like_percent 컬럼이 없으면 summer_like_ratio * 100을 통해 온더플라이로 즉시 생성합니다.

  수정된 app.py를 git commit & push하시면 배포 웹페이지에서 4개 전이월 트렌드, 히트맵, 시대별 비교 그래프가 모두 정상 작동합니다.
